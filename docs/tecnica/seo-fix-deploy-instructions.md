# Fix SEO indicizzazione documenti - Istruzioni deploy

Data: 2026-04-13

## Problema

Google classifica le pagine di `documenti.tenpennynovels.com` come "alternate" del dominio principale perche la sitemap era cross-domain: ospitata su `tenpennynovels.com` ma con URL di `documenti.tenpennynovels.com`.

## Cosa e cambiato nel codice

| File | Modifica |
|------|----------|
| `services/unified-backend/src/services/SitemapService.ts` | Ogni dominio genera il proprio `sitemap.xml` autonomo. Eliminati sitemap index e sub-sitemap. |
| `services/unified-backend/src/config/runtime/appConfig.ts` | Aggiunta `documentsSitemapOutputDir` (env: `DOCUMENTS_SITEMAP_OUTPUT_DIR`). |
| `apps/documents/public/robots.txt` | Sitemap punta a `https://documenti.tenpennynovels.com/sitemap.xml`. |
| `deploy/nginx-configs/documenti.tenpennynovels.com.conf` | Aggiunto location block per servire la sitemap. |
| `apps/documents/next.config.ts` | Nuovo file con `trailingSlash: false`, `poweredByHeader: false`. |

---

## 1. VPS - Environment variable

Il backend ora scrive in due directory. In produzione (PM2 senza Docker) i path si risolvono automaticamente via monorepo relativo, quindi **non serve** aggiungere env var se il backend gira dalla root del monorepo.

Se invece usi un path custom, aggiungi nel `.env.production` del unified-backend:

```bash
# Gia esistente (invariata)
SITEMAP_OUTPUT_DIR=/home/ubuntu/tenpennynovels/apps/landing/public

# Nuova: output per la sitemap dei documenti
DOCUMENTS_SITEMAP_OUTPUT_DIR=/home/ubuntu/tenpennynovels/apps/documents/public
```

## 2. VPS - Nginx

Copia la config aggiornata sul server:

```bash
# Dal VPS
sudo cp /home/ubuntu/tenpennynovels/deploy/nginx-configs/documenti.tenpennynovels.com.conf \
        /etc/nginx/sites-available/documenti.tenpennynovels.com

# Verifica sintassi
sudo nginx -t

# Ricarica
sudo nginx -s reload
```

Il blocco aggiunto e:

```nginx
# Sitemap (generated by backend cron)
location ~ ^/sitemap.*\.xml$ {
    proxy_pass http://127.0.0.1:4002;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    add_header Content-Type "application/xml; charset=UTF-8";
    add_header Cache-Control "public, max-age=3600";
}
```

## 3. VPS - Pulizia vecchi file sitemap

Dopo il deploy, rimuovi i file orfani dalla directory landing:

```bash
rm -f /home/ubuntu/tenpennynovels/apps/landing/public/sitemap-landing.xml
rm -f /home/ubuntu/tenpennynovels/apps/landing/public/sitemap-documents.xml
```

Il vecchio `sitemap.xml` (che era un sitemap index) viene sovrascritto automaticamente dalla prima generazione con il nuovo formato (urlset diretto).

## 4. VPS - Riavviare il backend per generare le nuove sitemap

```bash
cd /home/ubuntu/tenpennynovels

# Rebuild e restart del backend
pm2 restart tenpennynovels-unified-backend --update-env

# Verifica nei log che la generazione sia andata a buon fine
pm2 logs tenpennynovels-unified-backend --lines 30 | grep -i sitemap
```

Il backend genera le sitemap all'avvio, quindi dopo il restart troverai:
- `/home/ubuntu/tenpennynovels/apps/landing/public/sitemap.xml` (solo URL landing)
- `/home/ubuntu/tenpennynovels/apps/documents/public/sitemap.xml` (solo URL documenti)

## 5. Verifica che le sitemap siano raggiungibili

```bash
# Dal VPS o da locale
curl -s -o /dev/null -w "%{http_code}" https://tenpennynovels.com/sitemap.xml
# Deve restituire 200

curl -s -o /dev/null -w "%{http_code}" https://documenti.tenpennynovels.com/sitemap.xml
# Deve restituire 200

# Controlla il contenuto
curl -s https://tenpennynovels.com/sitemap.xml | head -5
# Deve mostrare <urlset> con URL tenpennynovels.com (NON <sitemapindex>)

curl -s https://documenti.tenpennynovels.com/sitemap.xml | head -5
# Deve mostrare <urlset> con URL documenti.tenpennynovels.com
```

## 6. Docker (se usi docker-compose)

Aggiungi il volume e la env var per il nuovo output dir nel `docker-compose.yml`, nel servizio `unified-backend`:

```yaml
environment:
  SITEMAP_OUTPUT_DIR: /sitemap-output-landing
  DOCUMENTS_SITEMAP_OUTPUT_DIR: /sitemap-output-documents

volumes:
  - ./apps/landing/public:/sitemap-output-landing
  - ./apps/documents/public:/sitemap-output-documents
```

Nota: il volume attuale `./apps/landing/public:/sitemap-output` va rinominato per chiarezza.

## 7. Google Search Console

### 7a. Verificare la proprieta `documenti.tenpennynovels.com`

1. Apri [Google Search Console](https://search.google.com/search-console)
2. Clicca "Aggiungi proprieta" (in alto a sinistra nel selettore)
3. Scegli "Prefisso URL" e inserisci `https://documenti.tenpennynovels.com`
4. Verifica la proprieta (DNS, HTML tag, o file - DNS e il metodo consigliato, probabilmente gia verificato se hai la proprieta dominio `tenpennynovels.com`)

### 7b. Sottomettere la nuova sitemap

1. Nella proprieta `documenti.tenpennynovels.com`, vai a **Sitemap** nel menu laterale
2. Inserisci `https://documenti.tenpennynovels.com/sitemap.xml`
3. Clicca "Invia"
4. Verifica che lo stato sia "Riuscito" con il conteggio URL corretto

### 7c. Rimuovere la vecchia sitemap dalla proprieta landing

1. Nella proprieta `tenpennynovels.com`, vai a **Sitemap**
2. Se presente `sitemap-documents.xml` o il vecchio `sitemap.xml` (index), rimuovili
3. Se necessario, sottometti di nuovo `https://tenpennynovels.com/sitemap.xml`

### 7d. Richiedere re-indicizzazione (opzionale)

Per velocizzare il processo, puoi richiedere la re-indicizzazione delle pagine principali:

1. Nella proprieta `documenti.tenpennynovels.com`, vai a **Controllo URL** (barra in alto)
2. Inserisci gli URL principali uno alla volta (es. `/ambientazione/introduzione/presentazione`)
3. Clicca "Richiedi indicizzazione"
4. Ripeti per le 5-10 pagine piu importanti

## 8. Tempistiche

- **Nginx e backend**: effetto immediato dopo deploy
- **robots.txt**: Google lo rilegge entro 24-48 ore
- **Nuova sitemap**: Google la processa entro qualche giorno
- **Rimozione status "alternate"**: puo richiedere 2-4 settimane per propagarsi completamente
- **Re-indicizzazione completa**: 4-8 settimane per tutte le pagine

## 9. Come monitorare il progresso

In Google Search Console, proprieta `documenti.tenpennynovels.com`:

1. **Pagine > Motivo "Pagina alternativa con tag canonical appropriato"**: questo conteggio deve scendere progressivamente
2. **Pagine > "Indicizzata, non inviata nella Sitemap"** o **"Inviata e indicizzata"**: questi conteggi devono salire
3. **Sitemap**: verifica che il conteggio "URL rilevati" corrisponda ai documenti pubblici

Se dopo 4 settimane la situazione non migliora, verifica:
- Che le pagine rispondano correttamente (200, non redirect)
- Che il tag `<link rel="canonical">` punti esattamente all'URL visitato
- Che nessuna pagina abbia `noindex` per errore
