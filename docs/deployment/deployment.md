# TenpennyNovels Production Deployment Guide - OVH Server

This guide covers the complete production deployment process for TenpennyNovels on OVH servers.
Based on the current monorepo architecture with 3 backend services and 6 frontend applications (static HTML).

## 🏗️ Deployment Architecture

### Backend Services (OVH VPS - SSH Required)
- **3 Node.js microservices** requiring runtime environment
- **MongoDB + Redis** via native system services
- **API Gateway** as single entry point (port 8000)
- **WebSocket integration** for real-time features

### Frontend Applications (OVH Web Hosting - FTP Compatible)
- **6 static HTML sites** generated via Next.js export
- **No server-side rendering** - pure static files
- **Independent deployment** per application

## 🎯 Prerequisites

### OVH VPS Requirements (Backend)
- **OS**: Ubuntu 20.04+ LTS or Debian 11+
- **Plan**: VPS SSD 2 or higher (2 vCores, 4GB RAM minimum)
- **CPU**: 2+ cores for backend services + database
- **RAM**: 4GB minimum (8GB+ recommended for production)
- **Storage**: 40GB+ SSD for application + database
- **SSH Access**: Required for Node.js runtime and services

### OVH Web Hosting Requirements (Frontend)
- **Plan**: Performance or Pro plan recommended
- **PHP Version**: Not required (static HTML only)
- **SSL**: Let's Encrypt certificates available
- **FTP Access**: Required for static file upload
- **Custom Domains**: Supported for subdomains

### Technical Requirements
- **Node.js**: v22.13.1 (as specified in package.json engines)
- **NPM**: v10.0.0+ (as specified in package.json engines)
- **Docker**: For MongoDB + Redis containers

## 🚀 Deployment Options Overview

### Backend Deployment (OVH VPS - SSH REQUIRED)
**Why SSH is Required:**
- Node.js runtime environment needs to be active 24/7
- MongoDB and Redis database services need system installation
- PM2 process manager for service monitoring and restart
- Real-time WebSocket connections need persistent server process
- Environment variables and security configurations

**Cannot Use FTP For Backend Because:**
- Static files cannot execute Node.js applications
- No runtime environment for database connections
- WebSocket server requires active Node.js process
- No process management or auto-restart capabilities

### Frontend Deployment (OVH Web Hosting - FTP COMPATIBLE)
**Why FTP Works for Frontend:**
- Static HTML/CSS/JS files generated by Next.js export
- No server-side rendering required
- All API calls go to backend via CORS
- Pure client-side React applications

## 🖥️ Backend Setup (OVH VPS via SSH)

### Step 1: Connect to OVH VPS
```bash
# SSH into your OVH VPS as ubuntu user (same user configured for FTP)
ssh ubuntu@your-ovh-vps-ip

# Or if root access is needed initially:
ssh root@your-ovh-vps-ip
```

### Step 2: System Preparation
```bash
# Update Ubuntu system
sudo apt update && sudo apt upgrade -y

# Setup application directory for FTP uploads
sudo mkdir -p /home/ubuntu/tenpennynovels
sudo chown ubuntu:ubuntu /home/ubuntu/tenpennynovels

# Grant ubuntu user sudo access (if not already)
sudo usermod -aG sudo ubuntu

# Continue as ubuntu user (FTP configured for this user)
cd /home/ubuntu/tenpennynovels
```

### Step 3: Install Dependencies
```bash
# Install Node.js 22.13.1 (exact version required)
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs

# Verify versions match project requirements
node --version  # Should be v22.13.1+
npm --version   # Should be v10.0.0+

# Install MongoDB 6.0 (native installation)
wget -qO - https://www.mongodb.org/static/pgp/server-6.0.asc | sudo apt-key add -
echo "deb [ arch=amd64,arm64 ] https://repo.mongodb.org/apt/ubuntu $(lsb_release -cs)/mongodb-org/6.0 multiverse" | sudo tee /etc/apt/sources.list.d/mongodb-org-6.0.list
sudo apt-get update && sudo apt-get install -y mongodb-org

# Install Redis (native installation)
sudo apt-get install -y redis-server

# Install PM2 process manager globally
sudo npm install -g pm2

# Install additional tools (no Python dependencies needed)
sudo apt-get install -y curl wget build-essential nginx certbot git

# Start and enable MongoDB and Redis
sudo systemctl start mongod && sudo systemctl enable mongod
sudo systemctl start redis-server && sudo systemctl enable redis-server
```

### Step 4: Deploy Backend Code

**Upload via FTP (as configured)**
```bash
# Application directory is already configured at /home/ubuntu/tenpennynovels
cd /home/ubuntu/tenpennynovels

# Upload backend files via FTP from your local machine
# FTP uploads will go directly to /home/ubuntu/tenpennynovels/
# Expected structure after FTP upload:
# /home/ubuntu/tenpennynovels/
# ├── services/
# │   ├── api-gateway/
# │   ├── authentication-backend/
# │   ├── game-backend/
# │   └── management-backend/
# ├── services/
# │   ├── shared/              # Shared utilities, types
# │   ├── database/            # MongoDB models (33+ models)
# │   └── config/               # Configuration files (JSON)
# ├── scripts/
# ├── package.json
# └── ecosystem.config.js

# After FTP upload, install dependencies
npm install

# Build backend services only (no frontend builds needed on VPS)
npm run build:backend
``` 

### Step 5: Verify Database Services
```bash

sudo systemctl status mongod
# Should show: active (running)

# Check Redis is running
```

### Step 4: Nginx Configuration (OVH VPS)
```bash
# Create Nginx configuration for API Gateway only
sudo nano /etc/nginx/sites-available/tenpennynovels-api
```

**Nginx Configuration for API Gateway (OVH VPS):**
```nginx
# Rate limiting for API requests
limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;
limit_req_zone $binary_remote_addr zone=auth:10m rate=5r/m;

# API Gateway upstream (single entry point)
upstream api_gateway {
    server 127.0.0.1:8000;
    keepalive 32;
}

# API Gateway Server (only backend API on VPS)
server {
    listen 80;
    listen 443 ssl http2;
    server_name api.tenpennynovels.com;
    
    # SSL Configuration
    ssl_certificate /etc/letsencrypt/live/api.tenpennynovels.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.tenpennynovels.com/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;
    
    # Security Headers
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Frame-Options "DENY" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    
    # CORS headers for frontend domains
    add_header Access-Control-Allow-Origin "https://tenpennynovels.com" always;
    add_header Access-Control-Allow-Origin "https://game.tenpennynovels.com" always;
    add_header Access-Control-Allow-Origin "https://docs.tenpennynovels.com" always;
    add_header Access-Control-Allow-Origin "https://forum.tenpennynovels.com" always;
    add_header Access-Control-Allow-Origin "https://gestione.tenpennynovels.com" always;
    add_header Access-Control-Allow-Origin "https://supporto.tenpennynovels.com" always;
    add_header Access-Control-Allow-Credentials "true" always;
    add_header Access-Control-Allow-Methods "GET, POST, PUT, DELETE, OPTIONS" always;
    add_header Access-Control-Allow-Headers "Content-Type, Authorization, X-Requested-With" always;
    
    # Handle preflight requests
    location / {
        if ($request_method = 'OPTIONS') {
            return 204;
        }
        
        # All API requests go through API Gateway
        limit_req zone=api burst=20 nodelay;
        proxy_pass http://api_gateway;
        
        # Proxy headers
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # WebSocket support
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_cache_bypass $http_upgrade;
    }
    
    # Authentication endpoints with stricter rate limiting
    location ~ ^/(auth|login) {
        limit_req zone=auth burst=3 nodelay;
        proxy_pass http://api_gateway;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# HTTP to HTTPS redirect for API domain
server {
    listen 80;
    server_name api.tenpennynovels.com;
    return 301 https://$server_name$request_uri;
}
```

## 📝 Complete OVH Deployment Summary

### Deployment Answer to Your Question

**Can backend be deployed via FTP?** 
❌ **NO** - Backend requires SSH access because:
- Node.js applications need active runtime environment
- PM2 process manager requires server access
- Docker containers (MongoDB/Redis) need system-level permissions  
- WebSocket connections require persistent processes
- Environment variables and security configurations need server setup

**Must backend deployment be done via SSH?**
✅ **YES** - SSH is required for:
- Installing Node.js, PM2, MongoDB, Redis (native installations)
- Starting and managing backend processes
- Database setup and seeding
- SSL certificate management
- System configuration

### Deployment Architecture Summary

**OVH VPS (SSH Required):**
- 1 API Gateway (port 8000) - single entry point
- 3 Backend Services (ports 3000-3002) - microservices  
- MongoDB + Redis (native system services)
- Nginx reverse proxy with SSL
- PM2 process management

**OVH Web Hosting (FTP Compatible):**
- 6 Static HTML applications (Next.js export)
- No server-side rendering
- Pure client-side React apps
- SSL certificates via OVH manager
